# PLAN: SPARQL tab, CONSTRUCT/ASK results, literal types, and querying inferred data

## Context
A client reported three SPARQL problems: (1) queries only see asserted triples, so inferred classes (RDFS/OWL) and SWRL-derived properties return nothing; (2) `CONSTRUCT { ?s ?p ?o } WHERE { ?s ?p ?o } LIMIT 5` fails with "unsupported file format: text/turtle"; (3) SELECT results lose literal datatype and language unless `DATATYPE()`/`LANG()` are selected. Read-only investigation found causes. Work happens on `feature/remove-openllet` (worktree `D:\wt-openllet`). No commit/push/deploy until told; no co-author line; dev only. (The report says "Openllet": the reasoner is now HermiT.)

## Findings
- `POST /api/sparql/query/{projectId}` (`SparqlQueryController.java:114-138`) never checks the query form. It always calls `execSelect` -> `execSelectGraphDB` (`SparqlDatasetService.java` ~1125-1160) -> `prepareTupleQuery`, so ASK/CONSTRUCT/DESCRIBE go down the tuple path; Fuseki answers CONSTRUCT with text/turtle and RDF4J throws. `execConstruct` (~1231) and `execAsk` (~1261) exist; `extractQueryType` exists; `SparqlText` has comment/prefix-aware helpers and `removeFromClauses`.
- `toValue()` (`SparqlQueryController.java:175-186`) returns `stringValue()` for every node, dropping datatype/lang; the plugin (`plugins/sparql-query-plugin/src/SparqlQueryEditor.tsx` 196-245, table ~667-676) guesses types from `startsWith('http')` and shortens values containing `/`.
- Storage is a plain Fuseki TDB2 dataset read through an RDF4J repository (`includeInferred` exists in `execSelect` but is never true; no ruleset configured). Reasoner results (HermiT snapshots) and SWRL Execute output are not in the SPARQL data; the only "include inferred" features are the class-instance and individual-assertion mergers (`ReasonerClassInstanceMerger`, `OntologyQueryController` ~902-996). SWRL conclusions are a capped (1000) UI list plus "Add selected".
- Draft reads go to a per-user draft graph (`SparqlGraphUris.userDraftGraph`, `SparqlDatasetService` ~835-863, `SparqlQueryContextInterceptor` reads `?draft=true`).

## Part 1: CONSTRUCT, DESCRIBE, ASK
- Detect the query form (`extractQueryType`, comment and prefix aware; reject update forms). SELECT unchanged.
- CONSTRUCT/DESCRIBE: run via `prepareGraphQuery` with the same graph scoping and `removeFromClauses` as SELECT (execConstruct does not strip user FROM today: add it), cap triples (existing result cap constant), return the requested format by `format` param or Accept: `text/turtle` (default), `application/ld+json`, `application/rdf+xml`, `application/n-triples` via Rio. JSON envelope for the UI: `{type:"graph", format, content, tripleCount, truncated, executionTime}`.
- ASK: `{type:"boolean", boolean, executionTime}`.
- SELECT stays `{head, results, executionTime}` plus `type:"select"`.
- Plugin: branch on `type`: show Turtle in the existing `<pre>` with a format dropdown, copy and download; show ASK as true/false chip; keep CSV/JSON export for SELECT.
- Errors: unsupported or malformed query returns 400 `{error}` in plain words ("This is an UPDATE; use the update tab"), never a raw library message.

## Part 2: literal datatype and language
- Add a parallel field `bindings` (W3C shape: `{var:{type:"uri|literal|bnode", value, datatype?, "xml:lang"?}}`), datatype only when not `xsd:string`, lang only when present. Keep `results` (plain strings) unchanged so other consumers do not break (graph-view `sparqlAsk.ts:43-47`, fuzzy plugin `FuzzyEditor*.tsx` and its bundle, tests).
- Plugin table renders from `bindings`: `"text"@en`, `"1"^^xsd:int`; shorten only real IRIs, never literals; CSV/JSON/copy exports include datatype and lang (new columns/format option, default unchanged).
- Tests: controller tests with a mocked dataset service for lang-tagged, typed, plain, IRI, bnode and the empty-string literal.

## Part 3: query inferred data (option A, per-request, recommended by investigation)
Toggle in the SPARQL tab: `Asserted only` (default) / `Include inferred`. Request field `includeInferred` plus optional `layers` (`owl`, `rules`).
- Build a temporary in-memory RDF4J `MemoryStore` per query scope: asserted triples of the target graph (project, or the user's draft graph when `?draft=true`) + inferred triples; run the user's query over that union; discard it. No persisted state, so edits, undo, PR snapshots, exports and drafts cannot leave anything stale or leak inferred triples.
- OWL layer: the HermiT reasoner result for the same ontology version (class hierarchy closure and instance types, property assertions it can produce): reuse the reasoner-worker snapshot/job path (`REASONER_SNAPSHOT`, `ReasoningSnapshotService`, `EditorReasonerCacheService` keys by project, revision, draft) and convert inferred axioms to triples with the OWLAPI RDF renderer. Step 1 of the work is a spike to confirm which inferred assertion kinds the snapshot exposes (subclass closure, types, object/data property assertions); where the snapshot lacks a kind (e.g. individual property assertions) fall back to computing it for the query with the cheapest sound method and report what is included.
- Rules layer: derived assertions from the rule loop (`RuleExecution`/`prepareChained`, rules are swrl:Imp in the graph): run it once per (ontology revision or draft version, rules fingerprint), cache the derived triples, and add them. Lift the 1000-axiom UI cap for this internal use (presentation cap stays for the Execute results screen). Rule execution has a real cost (about 0.6 s at 100 individuals, 19 s at 1000 individuals with the current loop; the speed-up work in progress should reduce it): run it as an async job with a timeout and say so in the response.
- Staleness and honesty: every inferred response carries `inferred:{ontologyRevision|draftVersion, reasoner:"HermiT", computedAt, layers, tripleCount, partial, stale}`. If no snapshot exists or it is older than the current revision, do NOT silently answer: respond 409 `{needsReasoning:true, message:"Run the reasoner first"}` or, when the user chose "Refresh now", compute it (async with progress), then query. The UI shows the snapshot time and a stale badge; the toggle is disabled with a tooltip when no reasoner result exists.
- Draft isolation: draft queries use the draft graph's own snapshot; public queries never see draft inferences; PR snapshot queries (frozen) use their frozen graph and are labelled; never read another user's draft.
- Limits: size guard (reuse the draft graph cap of 500k triples): above it refuse with a clear message and suggest narrowing; ELK note: ELK snapshots lack many OWL entailments, so the layer states the reasoner used, and the toggle uses HermiT for individuals unless the project is large (then the message explains).
- Semantics to document in the response and UI help: results include entailments HermiT can produce as explicit triples (subclass closure, types, property assertions); SWRL results are those the rule loop derives (comparison built-ins via OWL, others via the rule engine); anonymous individuals are ignored by rules; equality reasoning limits as listed by the rule loop.

## Part 4: Execute results paging (user question, 28 Oct)
Checked in code: `InferredAxiomPresenter.present` already drops trivial `SameIndividual` and `owl:Thing` assertions, lists new assertions (rule conclusions) first, then structure (TBox closure), and cuts the list at `swrl.max-inferred-axioms` (1000; conclusions get up to 10x that), setting `truncated`; the Results tab then shows "Only the first N are listed; the rest are cut off." There is NO real pagination: no page/offset in the response and no "show more" in the Execute results list. Fix: the Execute response keeps the full presented list server-side for the run (cached by run id with a short TTL, bounded) and `GET .../execute/{runId}/axioms?offset=&limit=&kind=conclusions|structure&q=` pages it; the Results tab pages (50 per page) with counts per kind ("7,599 derived: 4 rule conclusions, 7,595 structure"), conclusions tab first, structure tab collapsed by default, search over all pages, "Add selected" works across pages with a running selection count; keep the 1000 cap only for the first response payload. Tests: presenter paging, offset past end, TTL expiry gives 410 with "run Execute again", selection across pages in the plugin.
