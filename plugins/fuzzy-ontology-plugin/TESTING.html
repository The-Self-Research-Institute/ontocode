1. Overview

What is Fuzzy Ontology? (For Testers)

Standard Ontology Problem: "Is this patient diabetic?" → Binary answer: YES or NO

Real-World Problem: Medical reality is fuzzy! A patient might be:

  • "Somewhat diabetic" (early stage, pre-diabetic)
  • "Moderately diabetic" (diagnosed, controlled)
  • "Severely diabetic" (complications present)

Fuzzy Ontology Solution: Instead of YES/NO, express degrees of membership:

  • Patient A: Diabetic(0.95) ← "Almost certainly diabetic"
  • Patient B: Diabetic(0.50) ← "Borderline diabetic"
  • Patient C: Diabetic(0.10) ← "Unlikely to be diabetic"

Real-World Applications

DomainExampleWhy Fuzzy?
Healthcare Patient risk classification (low/medium/high) Risk isn't binary; patients span a spectrum
Banking Credit rating (poor/fair/good/excellent) Credit scores are continuous, not discrete buckets
E-commerce Product recommendations (poor/fair/good match) User preferences have shades, not absolute fits
IoT Sensors Temperature zones (cold/cool/warm/hot) Temperature gradients are continuous, overlapping

Key Testing Principles for Testers

  • ✓ Range Validation: All membership degrees must be between 0.0 and 1.0
  • ✓ Symmetry: If a function is symmetric, test it at equal distances from peak
  • ✓ Logic Consistency: Fuzzy AND/OR must obey De Morgan's Laws
  • ✓ Edge Cases: Test with extreme values (negatives, very large numbers, NaN)
  • ✓ Real Data: Run with actual domain data (patients, products, sensors)

The Fuzzy Ontology Plugin provides advanced fuzzy ontology support with membership degrees, fuzzy reasoning (T-norms, T-conorms), interactive visualization, and a custom query DSL — capabilities beyond standard Protégé.

3. Membership Function Tests

Why We Test Membership Functions

What are membership functions? They're the mathematical "bridges" that translate real-world values into fuzzy membership degrees. Example:

  • Input: A patient's age = 65 years
  • Function: "Elderly" membership function
  • Output: Degree = 0.75 ("fairly elderly")

Why test them? If membership functions are wrong, the entire reasoning system is broken. Bad membership functions → bad classifications → wrong decisions.

TC-FZ-001: Triangular Membership Function

Verify triangular membership function computes correct degrees

Why Triangular? (For Testers)

Shape: A triangle peaks at the center (b), declining to zero at edges (a and c). Used when there's a single "ideal" value.

Real-World Example: "Optimal Blood Pressure"

  • 80 mmHg (point a): Not optimal yet (degree 0.0)
  • 120 mmHg (point b): Perfect! (degree 1.0)
  • 160 mmHg (point c): Too high (degree 0.0)

How It Works (Mathematical)

For input x in range [a, b, c]:

  • If x ≤ a or x ≥ c: degree = 0.0 (outside range)
  • If a < x ≤ b: degree = (x - a) / (b - a) (rising line)
  • If b < x < c: degree = (c - x) / (c - b) (falling line)

Steps

  1. Open Fuzzy Editor
  2. Create a fuzzy class "Moderate" with triangular function (a=20, b=50, c=80)
  3. Test with values: 20, 35, 50, 65, 80, 90

Expected Results

InputMembership DegreeWhy This Value?
200.0Exactly at left edge (a)
350.5Halfway between a(20) and b(50): (35-20)/(50-20) = 0.5
501.0At peak (b)
650.5Halfway down from peak: (80-65)/(80-50) = 0.5
800.0Exactly at right edge (c)
900.0Outside range, beyond c(80)

Key Test Points (What Could Go Wrong?)

  • ✓ Symmetry: The distances from peak (50) should be symmetric (35 and 65 both give 0.5)
  • ✓ Peak: Value at peak must always be exactly 1.0
  • ✓ Range Bounds: Values at edges (a, c) must be exactly 0.0
  • ✗ Bug Example: If (35) returns 0.6 instead of 0.5, the formula calculation is broken

TC-FZ-002: Trapezoidal Membership Function

Verify trapezoidal function with flat top

Why Trapezoidal? (For Testers)

Shape: A trapezoid with a flat top. Used when there's a range of ideal values, not just one point.

Real-World Example: "Normal Blood Pressure Range"

  • 60-90 mmHg (rising): Getting closer to normal
  • 90-120 mmHg (plateau): All perfectly normal here!
  • 120-150 mmHg (falling): Getting above normal

How It Works (Mathematical)

For input x in range [a, b, c, d]:

  • If x ≤ a or x ≥ d: degree = 0.0 (outside range)
  • If a < x ≤ b: degree = (x - a) / (b - a) (rising line)
  • If b ≤ x ≤ c: degree = 1.0 (flat plateau - all equally good)
  • If c < x < d: degree = (d - x) / (d - c) (falling line)

Steps

  1. Create fuzzy class "Normal" with trapezoidal function (a=60, b=80, c=120, d=140)
  2. Test with values: 50, 70, 100, 130, 150

Expected Results

InputMembership DegreeWhy This Value?
500.0Below range (a=60)
700.5On rising edge: (70-60)/(80-60) = 0.5
1001.0In plateau zone (between b=80 and c=120)
1300.5On falling edge: (140-130)/(140-120) = 0.5
1500.0Above range (d=140)

Key Test Points (What Could Go Wrong?)

  • ✓ Plateau: All values in [b, c] must return 1.0 (the "equally good" zone)
  • ✓ Symmetry: If plateau is 40 units wide, left and right slopes should be proportional
  • ✗ Bug Example: If (100) returns 0.8 instead of 1.0, the plateau logic is broken

4. Fuzzy Reasoning Tests

Why We Test Fuzzy Reasoning

Problem: What happens when we combine multiple fuzzy memberships? For example:

  • "This patient is 80% diabetic AND 60% hypertensive"
  • How confident are we that both conditions apply? (Use AND operation)
  • How confident are we that at least one applies? (Use OR operation)
  • How confident are we that the patient is NOT diabetic? (Use NOT operation)

Why test this? These operations are the foundation of fuzzy rule inference. Wrong operations = wrong conclusions. This is where silent bugs hide!

Understanding T-norms and T-conorms

T-norms (AND): How to combine two conditions that both must be true?

T-conorms (OR): How to combine two conditions where at least one must be true?

OperationMin (Standard)ProductŁukasiewicz
T-norm (AND): 0.8 AND 0.6 min(0.8, 0.6) = 0.6 0.8 × 0.6 = 0.48 max(0.8+0.6-1, 0) = 0.4
T-conorm (OR): 0.8 OR 0.6 max(0.8, 0.6) = 0.8 0.8+0.6-(0.8×0.6) = 0.92 min(0.8+0.6, 1) = 1.0

Key Point: Different T-norm operations give DIFFERENT RESULTS! The plugin must consistently apply the correct one.

TC-FZ-007: T-Norm — Product (Fuzzy AND)

Verify Product T-norm computation

Test Data: Patient with Diabetic(0.8) AND Hypertensive(0.6)

Mathematical Formula: 0.8 × 0.6 = 0.48

Expected Result: 0.48

What if it fails? If result is 0.6 (min operation) instead of 0.48, the wrong T-norm is being used.

TC-FZ-008: T-Norm — Gödel/Min (Fuzzy AND)

Verify Gödel (minimum) T-norm

Test Data: Patient with Diabetic(0.8) AND Hypertensive(0.6)

Mathematical Formula: min(0.8, 0.6) = 0.6

Expected Result: 0.6

Why Min? For AND: confidence is limited by the weaker condition. If diabetic is 80% sure and hypertensive is only 60% sure, confidence in BOTH is 60%.

TC-FZ-009: T-Norm — Łukasiewicz (Fuzzy AND)

Verify Łukasiewicz T-norm

Test Data: Patient with Diabetic(0.8) AND Hypertensive(0.6)

Mathematical Formula: max(0.8 + 0.6 - 1, 0) = max(0.4, 0) = 0.4

Expected Result: 0.4

More Conservative: Łukasiewicz requires even more evidence than Product. Less forgiving of uncertainty.

TC-FZ-010: T-CoNorm — Probabilistic (Fuzzy OR)

Verify probabilistic T-conorm

Test Data: Patient with Diabetic(0.8) OR Hypertensive(0.6)

Mathematical Formula: 0.8 + 0.6 - (0.8 × 0.6) = 1.4 - 0.48 = 0.92

Expected Result: 0.92

Why? For OR: confidence in "at least one" is high if either is probable. Probabilistic avoids double-counting.

TC-FZ-011: T-CoNorm — Gödel/Max (Fuzzy OR)

Verify Gödel (maximum) T-conorm

Test Data: Patient with Diabetic(0.8) OR Hypertensive(0.6)

Mathematical Formula: max(0.8, 0.6) = 0.8

Expected Result: 0.8

Why Max? For OR: confidence is determined by the stronger condition. If diabetic is 80% likely, then "diabetic OR hypertensive" is at least 80% likely.

TC-FZ-012: T-CoNorm — Łukasiewicz (Fuzzy OR)

Verify Łukasiewicz T-conorm

Test Data: Patient with Diabetic(0.8) OR Hypertensive(0.6)

Mathematical Formula: min(0.8 + 0.6, 1) = min(1.4, 1.0) = 1.0

Expected Result: 1.0

Most Permissive: Łukasiewicz is most generous with OR. Combined degrees that exceed 1.0 are capped at 1.0.

TC-FZ-013: Fuzzy Negation — Standard

Verify standard fuzzy negation (1 - x)

Test Data: Diabetic(0.8)

Why NOT Operation? If a patient is 80% diabetic, they're 20% "not diabetic" (or more precisely, 20% likely to NOT have diabetes).

Mathematical Formula: NOT(x) = 1 - x = 1 - 0.8 = 0.2

Expected Result: NOT Diabetic = 0.2

Key Property: Standard negation is linear and symmetric. If you negate twice: NOT(NOT(0.8)) = 1 - (1 - 0.8) = 0.8 ✓

TC-FZ-014: Fuzzy Negation — Sugeno

Verify Sugeno negation

Test Data: Degree 0.8, parameter λ=2

Why Sugeno? Sugeno negation is less "harsh" than standard. It's used when you want to be more conservative about negation.

Mathematical Formula: NOT_λ(x) = (1 - x) / (1 + λx)

For x=0.8, λ=2: (1 - 0.8) / (1 + 2×0.8) = 0.2 / (1 + 1.6) = 0.2 / 2.6 ≈ 0.077

Expected Result: ≈ 0.077

Compare: Standard would give 0.2, but Sugeno gives 0.077 (less membership in NOT diabetic). Sugeno is more permissive toward original membership.

TC-FZ-017: Alpha-Cut Reasoning

Verify alpha-cut based filtering

What is an Alpha-Cut?

Simple Explanation: A threshold for membership. "Give me all patients who are diabetic with at least 70% confidence."

Formula: Alpha-cut at 0.7 = {x : μ(x) ≥ 0.7}

Use Case: Risk classification - only high-risk patients (≥0.8) get early intervention.

Steps

  1. Set alpha threshold to 0.7
  2. Query fuzzy class "Diabetic"
  3. Verify: only individuals with membership ≥ 0.7 returned

Expected Results

  • Patient A (Diabetic 0.85): ✓ Included (≥ 0.7)
  • Patient B (Diabetic 0.65): ✗ Excluded (< 0.7)
  • Different alpha values produce different result sets
  • Alpha 0.9 produces smaller set than Alpha 0.7

TC-FZ-018: Fuzzy Rule Inference

Verify fuzzy rule creates new memberships

What is Fuzzy Rule Inference?

Rule: IF Diabetic(x) ≥ 0.7 AND BMI(x) > 30 THEN HighRisk(x) = min(Diabetic(x), Obese(x))

In Plain English: "If someone is fairly diabetic (≥70%) AND obese, then classify them as high risk. The risk degree is the minimum of their diabetes and obesity scores."

Real Example:

  • Patient A: Diabetic(0.85) AND Obese(0.75) → HighRisk = min(0.85, 0.75) = 0.75
  • Patient B: Diabetic(0.65) AND Obese(0.90) → Rule condition fails (diabetic < 0.7), no HighRisk membership
  • Patient C: Diabetic(0.80) AND Obese(0.40) → HighRisk = min(0.80, 0.40) = 0.40 (lower risk due to lower obesity)

Steps

  1. Create rule in Fuzzy Editor rules tab
  2. Define condition: Diabetic(x) >= 0.7 AND BMI(x) > 30
  3. Define action: HighRisk(x) = min(Diabetic(x), Obese(x))
  4. Execute rule against patient population

Expected Results

  • Matching individuals get HighRisk membership
  • Degree computed from rule formula (min in this case)
  • New memberships visible in membership table
  • Non-matching individuals have no HighRisk membership (or 0.0)

5. Fuzzy Query DSL Tests

What is Fuzzy Query DSL?

Standard Query: "SELECT all diabetic patients" → All-or-nothing match

Fuzzy Query: "FIND patients who are fairly diabetic (≥0.8)" → Partial matches with degrees

Benefit: You can rank results by confidence instead of binary yes/no.

TC-FZ-019: Basic Membership Query

What This Tests

Simple threshold query: "Give me patients with strong diabetic diagnosis (at least 80% confident)."

Query

FIND individuals WHERE memberOf(Diabetic) >= 0.8

Expected Results

  • Only individuals with Diabetic membership ≥ 0.8 returned
  • Example: Patient001(0.85), Patient003(0.92) → Included; Patient002(0.75) → Excluded
  • Results show entity IRI and membership degree

TC-FZ-020: Compound Condition Query (AND)

What This Tests

Complex query combining fuzzy conditions: "Find patients who are both diabetic AND hypertensive with combined confidence > 60%."

Query

FIND individuals WHERE memberOf(Diabetic AND Hypertensive) > 0.6

How It Works

  • For each patient, compute: min(μ_Diabetic, μ_Hypertensive)
  • Patient A: min(0.8, 0.7) = 0.7 ✓ Included (> 0.6)
  • Patient B: min(0.9, 0.5) = 0.5 ✗ Excluded (≤ 0.6)

Expected Results

  • Fuzzy AND (T-norm/min) applied between memberships
  • Only combined degree > 0.6 returned
  • T-norm type respects current configuration (min by default)

TC-FZ-021: Top-N Query with Ordering

What This Tests

Ranking query: "Show me the 10 highest-risk patients, sorted by risk level."

Query

SELECT TOP 10 FROM Patient ORDER BY memberOf(HighRisk) DESC

Expected Results

  • Returns maximum 10 patients
  • Ordered by HighRisk membership degree descending (highest risk first)
  • Example output: Patient001(0.95), Patient005(0.88), Patient012(0.82), ...
