RRecommendation by Use Case

🧑‍💻 Solo Developer / Demo

Best pick: t3.large (current)
Cheapest option. Works for small ontologies and 1–2 users. Not for production workloads.

👥 Small Team (3–5 users)

Best pick: t3.xlarge
2× the RAM. Handles medium ontologies. Minimum viable for a real team. ~$120/mo.

🏢 Production (10–20 users)

Best pick: t3.2xlarge
Best cost-per-user ratio. Handles large ontologies, concurrent imports, SWRL. The sweet spot at ~$240/mo.

⚡ Production + Large Ontologies

Best pick: m6i.2xlarge
No burst CPU = consistent performance. Best for sustained workloads, large imports, predictable latency. ~$280/mo.

💰 Budget Production

Best pick: r6i.xlarge
32GB RAM at only ~$190/mo. Memory-optimized — great for GraphDB. Fewer vCPUs means lower concurrency.

🏗️ Enterprise (50+ users)

Best pick: Multiple instances + LB
No single instance handles 50+ users. Deploy multiple editor instances behind a load balancer with shared GraphDB.

⚠ Your t3.large — Bottom Line

It works for 1–2 developers testing with small/medium ontologies (<10MB). These will cause problems:

  • Importing a 50MB+ ontology — OOM crash likely
  • 5+ users browsing simultaneously — response times degrade to seconds
  • SWRL rules on large ontologies — SWRL container will be killed
  • Running for weeks without restarts — memory leaks compound
  • Sustained CPU load — burst credits deplete, drops to 30% baseline

Next step: When ready for production, upgrade to t3.2xlarge for the best value, or m6i.2xlarge for guaranteed performance.
