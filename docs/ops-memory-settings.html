Rate limiting: not enabled on dev

The auth RateLimitingFilter reads security.rate-limit.requests-per-minute but never uses it: the buckets are hard-coded at 100 per minute per IP for general calls, 10 for login/register/password calls and 15 for billing writes. /actuator/ paths are exempt. Two further facts: the dev compose runs auth with SPRING_PROFILES_ACTIVE=dev, and application-dev.properties sets security.rate-limit.enabled=false, which wins over the RATE_LIMIT_ENABLED variable; and behind the gateway every user may share one client address. Setting RATE_LIMIT_ENABLED=true and RATE_LIMIT_RPM=600 would therefore either do nothing or cap everyone at 100 per minute. It was not set. A code change (use the configured number, key by user) is needed first.

Swap on the dev host

The dev host has no swap. A 4 GiB swap file is recommended so a short spike slows down instead of triggering the OOM killer. This is a manual host step and was not done here.
