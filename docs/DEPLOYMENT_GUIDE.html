OntoCode deployment guide (overview)

This document summarizes how to deploy OntoCode with Docker Compose. For environment-specific runbooks use UAT deployment guide and Production deployment guide. For a complete EC2 walk-through (Docker only, no Kubernetes), see EC2 Docker production runbook. Adjust hostnames, secrets, and image registry for your environment.

1. Architecture overview

A typical stack includes:

  • MongoDB — application data and users.
  • GraphDB — RDF triple store for ontologies.
  • Auth service — authentication, workspaces, billing integration.
  • API gateway — routes HTTP traffic to backend services.
  • Ontology editor (owl-editor) — ontology upload, SPARQL, mutations.
  • SWRL service — rule execution.
  • Plugin service — plugin API.

Compose files in the repository root orchestrate these services. Use docker-compose.yml for local development. Use docker-compose.production.yml for UAT and production parity (larger GraphDB heap and memory); see the UAT and production HTML guides for which env file and Stripe mode to use.

2. Prerequisites

  • Docker and Docker Compose v2.
  • GraphDB license file (see repository .env.example for GDB_LICENSE_FILE / GDB_LICENSE_PATH).
  • Strong JWT_SECRET and unique MongoDB root credentials for production.
  • Optional: Stripe keys and price IDs for billing; SMTP for email.

3. Environment configuration

Copy .env.example to .env at the repository root and set values. Important groups:

UAT and production: Use long random JWT_SECRET, restrict MongoDB and GraphDB to internal networks where possible, and set BASE_URL to your public HTTPS origin so email links and redirects are correct. See the environment-specific guides for Stripe test versus live keys.

4. Build or pull images

Compose references images such as ${DOCKER_REGISTRY}/ontocode-auth:${VERSION}, ontocode-gateway, ontocode-editor, ontocode-swrl, ontocode-plugin, and optionally a custom GraphDB image.

  • Set DOCKER_REGISTRY and VERSION in .env to match your registry and tag.
  • Build services locally if you maintain Dockerfiles in-repo (e.g. GraphDB in production compose).

5. Start the stack (Docker Compose)

From the repository root:

docker compose --env-file .env up -d

For an alternate file:

docker compose -f docker-compose.production.yml --env-file .env up -d

Wait for health checks: MongoDB, GraphDB, then graphdb-init creates the ontocode repository if missing. Editor and SWRL depend on GraphDB and MongoDB.

Point the web client or VS Code extension at GATEWAY_URL or the appropriate host for API calls.

7. Health and operations

  • Editor liveness: GET http://<editor-host>:8083/actuator/health/liveness
  • GraphDB: GET http://<graphdb-host>:7200/rest/repositories
  • Logs: compose maps host paths such as /var/log/ontocode/auth, gateway, editor, swrl — create these directories or adjust volumes.

8. Stripe webhooks

Configure Stripe to send webhooks to your auth service billing endpoint (path is under the auth service in this project, e.g. /api/billing/webhook on the host that reaches auth). Set STRIPE_WEBHOOK_SECRET to the signing secret from the Stripe Dashboard. For local testing, Stripe CLI can forward events to your machine.

9. Kubernetes (optional)

The repository includes k8s/ingress.yaml as an example: TLS hosts, nginx ingress class, large body size and long proxy timeouts for uploads. Map backend.service names and ports to your actual Services. Review paths and ports for each microservice before applying to a cluster.

10. Upgrades

  1. Back up MongoDB and GraphDB volumes.
  2. Pull new images or rebuild with a new VERSION tag.
  3. Run docker compose up -d to recreate containers.
  4. Run smoke tests: login, open project, run a SPARQL query, billing webhook test if applicable.

11. Troubleshooting

  • GraphDB not ready: Check license mount and heap; wait for graphdb-init logs.
  • Auth fails or 401: Verify JWT_SECRET matches across gateway and services; check token expiry.
  • Upload timeouts: Increase gateway and ontology timeout environment variables consistently.
  • Billing out of sync: Confirm webhook URL and secret; inspect auth logs for Stripe handler errors.
