OntoCode UAT deployment guide

UAT (user acceptance testing) is a shared environment for validating releases, integrations, and billing flows before production. It should mirror production topology closely while using non-live payment credentials and disposable or restorable data. Companion: Production deployment guide.

1. Goals and boundaries

  • Same services as prod: MongoDB, GraphDB, auth, gateway, ontology editor, SWRL, plugin service, webapp — so behaviour matches production.
  • Stripe test mode only: STRIPE_SECRET_KEY must be sk_test_...; price IDs must be test-mode price_... from your Stripe test dashboard.
  • Separate data: UAT must not use production MongoDB, GraphDB, or secrets. Use its own hosts, volumes, and JWT_SECRET.
  • Safe to reset: Plan how to wipe or restore UAT data after major billing experiments (see scripts/payment-test only against UAT MongoDB).

2. Compose file and images

Use docker-compose.production.yml when you want the same layout and GraphDB sizing as production (recommended for UAT parity). Use docker-compose.yml for a lighter local-style stack on smaller hosts.

docker compose -f docker-compose.production.yml --env-file .env.uat up -d

Set DOCKER_REGISTRY and VERSION (or image tags your CI publishes) so UAT pulls explicit candidate builds, for example a release candidate tag rather than latest.

3. Environment variables (UAT)

Copy .env.example to a UAT-only file (for example .env.uat). Never commit it. Below is how key variables should behave in UAT versus production.

VariableUAT expectation
BASE_URLPublic HTTPS URL of the UAT webapp (used in invitation and password-reset emails). Example: https://uat.yourdomain.example.
AUTH_SERVICE_URL / GATEWAY_URLURLs clients use to reach auth and gateway from outside the cluster or host (ports depend on your ingress; gateway is often port 80 behind a load balancer).
JWT_SECRETLong random string, unique to UAT, not reused in prod or dev laptops.
MONGO_ROOT_USER / MONGO_ROOT_PASSWORDStrong credentials; UAT database must not point at production.
MONGODB_DATABASETypically ontocode or a UAT-specific name; must match connection strings in all services.
GRAPHDB_REPOSITORYUsually ontocode; separate GraphDB instance or repository from production.
STRIPE_SECRET_KEYTest secret key only (sk_test_...).
STRIPE_PUBLISHABLE_KEYTest publishable key (pk_test_...).
STRIPE_WEBHOOK_SECRETSigning secret from a Stripe test webhook endpoint pointing at UAT auth, e.g. https://uat-auth.../api/billing/webhook, or from stripe listen during manual tests.
STRIPE_PRICE_*Test price IDs for Pro / Enterprise monthly and yearly plans.
STRIPE_TRIAL_PERIOD_DAYSCan match prod or be shortened for faster UAT cycles.
SMTP_* / EMAIL_FROMUse a mail sink or non-customer domain (e.g. transactional provider subaccount) so UAT emails never go to real customers.
BILLING_REMINDER_ENABLED / BILLING_REMINDER_DAYS_BEFORE_LIST / cronsEnable to validate reminder jobs; use safe recipient lists.
GATEWAY_HTTP_RESPONSE_TIMEOUT / ONTOLOGY_HTTP_TIMEOUT_*Match production values if you test large uploads in UAT.
ADMIN_EMAIL / ADMIN_PASSWORDBootstrap admin for UAT only; rotate if exposed.
JIRA_*Optional; point at a test Jira project if issue reporting is validated in UAT.
LOGGING_LEVEL_ROOTINFO or DEBUG for deeper troubleshooting; avoid permanent DEBUG in production.

The auth service reads BILLING_REMINDER_DAYS_BEFORE_LIST (comma-separated integers). Compose passes this into the auth container; ensure your .env.uat defines it, not a deprecated single-day variable name.

4. Stripe webhooks in UAT

Create a Stripe test mode webhook endpoint whose URL reaches the UAT auth service path /api/billing/webhook. Copy the endpoint signing secret into STRIPE_WEBHOOK_SECRET. For ad-hoc developer testing from a laptop, Stripe CLI can forward to a tunnel URL; that secret belongs only on that machine, not in shared UAT unless you rotate it.

5. Smoke checklist after deploy

  1. GraphDB: repository ontocode exists; REST responds.
  2. Auth: register or login; token works through gateway.
  3. Editor health: /actuator/health/liveness on port 8083.
  4. Webapp loads and calls gateway-backed APIs.
  5. Billing: subscribe with a Stripe test card; confirm webhook rows and subscription state in MongoDB.

For deeper billing scenarios see PAYMENT_TESTING.html if present in your tree.

6. Networking and ingress

UAT hostnames (for example uat-api.example.com) should be distinct from production. TLS certificates can use a separate certificate or the same wildcard with a UAT subdomain. If you reuse k8s/ingress.yaml patterns, duplicate and edit hosts and backend services for the UAT namespace only.

7. Upgrades and rollback

Tag each UAT deployment with a git SHA or semver in VERSION. Keep the previous image tag available; rollback is docker compose ... up -d with the prior VERSION after restoring a database snapshot if schema changed.
